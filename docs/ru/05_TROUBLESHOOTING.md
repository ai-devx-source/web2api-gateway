# 05. Решение проблем (Troubleshooting)

В этом документе собраны наиболее частые проблемы, которые могут возникнуть при использовании `ApiConnector`, и способы их решения.

## 1. Как проверить, работает ли провайдер?

Самый простой способ проверить работоспособность любого провайдера — использовать встроенную утилиту тестирования.

1. Запустите шлюз: `npm start`
2. В появившемся меню выберите пункт **Test API connection** (обычно под номером 3 внутри меню настройки конкретного провайдера).
3. Шлюз отправит тестовый запрос (например: *"Hello, this is an automated diagnostic test..."*) и выведет результат в консоль.
4. Вы также можете посмотреть статусы (OK / Fail) всех провайдеров в главном меню.

---

## 2. Модель не найдена в списке (Open WebUI / LobeChat)

Если вы подключили шлюз к клиенту, но в списке доступных моделей пусто:

- **Проблема**: Вы не авторизовали ни одного провайдера. Шлюз передает клиенту список моделей только от тех провайдеров, которые успешно прошли проверку и имеют валидные токены.
- **Решение**: Запустите `npm run <provider>:auth` (например, `npm run qwen:auth` или `npm run perplexity:auth`) и убедитесь, что тест провайдера показывает статус **OK** в главном меню шлюза. Затем нажмите кнопку "Обновить список моделей" в настройках клиента.

---

## 3. Ошибка "fetch failed" при обращении к провайдерам

- **Симптомы**: При попытке отправить запрос (например, к DeepSeek) шлюз выдает ошибку `fetch failed` или падает по таймауту.
- **Причина**: Обычно это связано с блокировкой со стороны Cloudflare (особенно у DeepSeek, Perplexity, Kimi). Защита видит, что запрос идет не из настоящего браузера, и разрывает соединение на сетевом уровне.
- **Решение**: 
  - Обновите токен сессии (cookie) с помощью скриптов авторизации (см. `02_PROVIDERS_GUIDE.md`).
  - Убедитесь, что заголовки `User-Agent` и `Sec-Ch-Ua`, которые использует шлюз (в исходном коде), соответствуют современным версиям Chrome. Шлюз старается подменять их автоматически.
  - Если проблема постоянная, попробуйте переключить провайдера в режим DOM-проксирования (через Advanced Options -> Toggle Provider Transport Mode в меню).

---

## 4. Скрипт авторизации не может запустить браузер

- **Симптомы**: При запуске `npm run kimi:auth` или `npm run deepseek:auth` возникает ошибка Puppeteer (браузер не найден или отсутствует `libnss3.so`).
- **Решение (на Linux / WSL / Docker)**: Вам может не хватать системных библиотек для запуска Chrome. Установите их командой:
  ```bash
  sudo apt-get install -y libxss1 libappindicator1 libindicator7 xvfb libasound2 libgbm1 libnspr4 libnss3
  ```
- **Альтернатива**: Используйте провайдеров, для которых требуется простое копирование Cookie из вашего основного браузера (Perplexity, MIMO, HuggingFace), так как им не требуется запуск Puppeteer.

---

## 5. Ошибки 401 Unauthorized / 403 Forbidden

- **Причина**: Токен сессии просрочен.
- **Решение**: Повторно выполните процедуру авторизации через `npm run <provider>:auth`.

---

## 6. Как включить отладку?

Если вы хотите увидеть более подробные логи или посмотреть, что происходит в скрытом браузере при отправке запросов (в режиме DOM Proxy):

1. Запустите шлюз `npm start`.
2. Выберите пункт **Advanced Options**.
3. Выберите **Toggle Visible Browser (Debug Mode)**. 
   Теперь при выполнении запросов, использующих браузер, вы будете видеть само окно браузера.
